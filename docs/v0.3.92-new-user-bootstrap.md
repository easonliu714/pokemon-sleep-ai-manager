# v0.3.92 New User Database Bootstrap Freeze Closure

## Scope

- Treat cleared browsing history, an empty IndexedDB database store, and a deliberately cleared local SQLite database as supported new-user states.
- Use a dedicated fresh-database bootstrap path that creates only the current schema required for an empty personal profile.
- Do not replay historical shared-master data rewrites or canonicalization against a database that contains no player data.
- Make existing-database migrations idempotent by checking `schema_migrations` before each versioned migration.
- Yield to the browser between SQL.js initialization, SQLite open, schema preparation, migration, and first persistence stages.

## Safety

- No existing player row is deleted or overwritten by the fresh path.
- The fresh path is selected only when `schema_migrations` is empty after opening the local SQLite database.
- Existing databases continue through the normal migration path, but already-applied versions are skipped.
- Public catalog rendering remains independent from private SQLite quantities and unlock states.

## Live validation gates

1. Clear browsing history only: existing IndexedDB data remains loadable.
2. Clear site data / IndexedDB: application creates an empty personal database and becomes interactive.
3. Use the in-app clear database action: reload creates a fresh database and becomes interactive.
4. Existing database: no repeated shared-master or canonical migration on every startup.
5. Rescue-to-normal transition: the page must remain responsive and expose startup stages.
