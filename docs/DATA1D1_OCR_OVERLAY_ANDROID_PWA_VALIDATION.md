# DATA.1D.1 OCR Overlay Android PWA 實機驗證

## 前置條件

- 使用 Android Chrome 安裝最新版 PWA。
- 頁首版本顯示至少為 `v0.3.51`。
- 重新載入一次，確認 Service Worker 已更新。
- 準備一個包含 20、50、100 張 Pokémon Sleep 截圖的 ZIP 測試組。

## 驗證項目

1. 選擇 ZIP，確認解壓、SHA-256 與本機 OCR 能完成。
2. 點擊待覆核圖片，確認縮圖與辨識區域 overlay 正確顯示。
3. 快速連續切換至少 30 張圖片，最新點擊項目不得被舊請求覆蓋。
4. 切換 full image 與其他 region preset，overlay 必須同步更新。
5. 重複預覽相同圖片，不得出現舊縮圖殘留或錯圖。
6. 按停止 OCR，縮圖 overlay 應清除，頁面仍可操作。
7. 匯入另一個 ZIP，上一批圖片不得殘留。
8. 將 PWA 切到背景再回前景，確認沒有白畫面或卡死。
9. 關閉並重開 PWA，確認私人圖片未被永久保存。
10. 斷網重開 PWA，確認介面可由 cache 啟動；OCR runtime CDN 未快取時須有可理解錯誤。

## 效能觀察

- 20 張 ZIP：記錄完成時間、最高記憶體感受與是否卡頓。
- 50 張 ZIP：記錄完成時間、切圖延遲與取消回應時間。
- 100 張 ZIP：確認不崩潰；若裝置記憶體不足，應可停止而非整頁失效。
- 連續切圖 30 次後，操作延遲不可持續惡化。

## PASS 標準

- 無錯圖、無舊請求覆蓋、無持續 loading。
- 取消、換來源、關閉頁面後 overlay 均被清除。
- PWA 不崩潰、不白畫面、不需強制清除網站資料才能恢復。
- 私人圖片不出現在重新啟動後的 IndexedDB、localStorage 或匯出資料中。
- 診斷中心可匯出完整 Debug Trace，且不含圖片原始內容或 base64。

## 回報資料

- Android 裝置型號與 RAM。
- Android 與 Chrome 版本。
- PWA 顯示版本。
- ZIP 圖片數量及總容量。
- 各測試完成時間。
- 發生異常時的畫面截圖與診斷 JSON。
