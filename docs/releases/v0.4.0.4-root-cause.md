# v0.4.0.4 Root Cause

The Update Center guide treated `applyBtn.disabled` as a proxy for step-4 failure after Dry Run. However, `app.js` also disables `applyBtn` immediately after a successful `applyPayload()` call to prevent a second Apply. Because the guide had no explicit terminal `applied` state, a successful import could be rendered as a blocked step 4 (`Dry Run 尚未達到可套用`).

The fix reads the Dry Run update ID and checks `import_batches` in SQLite. A matching import batch is terminal success and takes precedence over read-only/blocked interpretation.
