# v0.4.0.4 — Post-Apply Terminal State + Inventory Summary

## Live findings
- Ingredient and item inventory JSON packages validate, Dry Run and Apply successfully.
- After Apply, the guided four-step flow can still render step 4 as blocked because `applyBtn` is intentionally disabled after a successful write while the guide does not yet model the terminal applied state.
- The permanent red danger styling of the enabled Apply button is visually confusable with a failed workflow state.
- Ingredient and item pages lack quick aggregate totals for visual reconciliation after import.

## Runtime changes
- Resolve the currently selected Dry Run update ID from the preview and verify it against `import_batches`.
- When the update ID is already recorded after Apply, render step 4 as completed instead of `Dry Run 尚未達到可套用`.
- Use a green ready-to-apply visual only while Apply is enabled; red is no longer used as the apparent readiness indicator.
- Add SQLite-backed aggregate cards above inventory tables.
  - Ingredient: category count, total quantity, stocked categories, zero-stock categories.
  - Item: category count, total quantity, reserved quantity, available quantity.
- Aggregates are explicitly based on committed local SQLite values, not unsaved input edits.

## Safety
- No schema migration.
- No inventory data rewrite.
- No import contract change.
- Existing Snapshot / Transaction / duplicate-update protections remain authoritative.
